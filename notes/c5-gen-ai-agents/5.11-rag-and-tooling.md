## Before RAG
- Models were **static knowledge bases**, limited to their training data, and updating them needed **retraining or fine-tuning**. Results could be **outdated, irrelevant or not company-specific**.
- Pre-RAG agents could **fetch** information with tools, but used it **only for the immediate query**. They couldn't process and integrate it.
- **RAG** lets models **retrieve and use tool-provided data**. To make a real difference, your agent should work from **your company's data**.

## How RAG works with tools (after the user query)
1. **Retrieval:** the LLM uses retrieval tools to find relevant documents or passages.
   - **Data stores:** internal databases, structured and unstructured.
   - **Vector databases:** store **embeddings** (numerical representations of text). The query is embedded and matched to **semantically similar** content.
   - **Search engines** (via extensions or APIs): web pages, articles.
   - **Knowledge graphs:** structured stores of **entities and relationships**, queried for facts.
2. **Augmentation:** the retrieved context is **added to the prompt** with the original query.
3. **Generation:** the LLM answers from the augmented prompt, more informed and accurate, and can **cite sources** (transparency, trust).
4. **Iteration** (in some systems): refine the query, try other retrieval tools, or ask the user **clarifying questions**.

## Data stores in AI Applications
- Knowledge bases your agent draws on. Options:
  - **Websites:** current events or public information.
  - **Structured data:** tables or **JSON** (product catalogues, customer databases, internal KBs). Agent Platform can **auto-detect** the structure, or you define it.
  - **Unstructured data:** **HTML, PDF, DOCX** files.

## Knowledge check
- Fetch relevant documents for a query → **Retrieval**.
- Add context from the knowledge base to the query → **Augmentation**.
- Produce the natural-language answer → **Generation**.
