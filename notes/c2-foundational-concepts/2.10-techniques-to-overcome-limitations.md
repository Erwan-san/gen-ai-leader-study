# 2.10 Techniques to overcome limitations
Course 2 · activity 607920 · no video

## 1. Grounding
- **Definition:** connecting AI output to **verifiable sources of information**. It tethers the model to real-world data and reduces invented content.
- **Benefits:**
  - **reduces hallucinations**;
  - **anchors responses** in your provided data;
  - **builds trust** through **citations and confidence scores**, so you can verify.
- You can ground in **enterprise data** or with **Google Search**.

## 2. Retrieval-augmented generation (RAG): a grounding method
RAG uses search to find relevant information in a knowledge base and passes it to the LLM as context. Three phases:
1. **Retrieval:** a search engine finds relevant information. It uses an index that understands **semantic meaning, not just keywords**, so relevance is higher.
2. **Augmentation:** the retrieved information is **added to the prompt**.
3. **Generation:** the model answers using the augmented prompt **plus its existing knowledge**.

## 3. Prompt engineering
- The **fastest and simplest** way to give a model extra background: precise prompts steer it to the desired output.
- **Limit:** it's bounded by the model's existing knowledge. It can't produce what the model never learned.

## 4. Fine-tuning
- **When:** prompt engineering doesn't deliver; you need excellence on **specific tasks** or **specific output formats**, especially when you **have examples of the desired output**.
- **What:** **further training** a pre-trained or foundation model on a **new task-specific dataset**, which **adjusts the model's parameters**. **Agent Platform** provides tuning tools.
- **Examples:** creative content in a specific style; code in a particular language; translation for specific languages or domains.

## 5. Humans in the loop (HITL)
Human input and feedback are built into the ML process for tasks needing judgement, context, or handling of incomplete data:
- **Content moderation:** catch harmful or inappropriate user content that algorithms miss.
- **Sensitive applications:** oversight in **healthcare and finance**.
- **High-risk decision making:** e.g. **medical diagnoses, criminal justice assessments**. A human review and accountability layer.
- **Pre-generation review:** experts validate outputs **before deployment**, catching errors and bias.
- **Post-generation review:** continuous review **after deployment** to adapt to changing contexts and needs.

## Knowledge check answers
- Adapting the model with task-specific data → **Fine-tuning**.
- Crafting precise instructions → **Prompt engineering**.
- Augmenting the model with external knowledge → **RAG**.
- Purpose of grounding → **accuracy and reliability by connecting output to verifiable sources** (not creativity, simplicity or speed).

## Summary table: RAG vs fine-tuning vs grounding
| | RAG | Fine-tuning | Grounding |
|---|---|---|---|
| **Definition** | Retrieves relevant information from external knowledge bases and adds it to the prompt | Further trains a pre-trained model on a new dataset for a task or domain | Connects output to verifiable sources |
| **Process** | Retrieve → add to prompt → generate | Select pre-trained model → gather data → train → evaluate & refine | Provide access to data sources → use RAG or fine-tuning to connect output |
| **Data sources** | External knowledge bases (databases, documents, internet) | Task- or domain-specific datasets | External knowledge bases or specific datasets |
| **Relation to grounding** | **A specific technique for** grounding | **Improves** a model's ability to be grounded in specific domains | **The overarching goal** |

## Exam hooks
- Decision rule:
  - quick improvement → prompt engineering;
  - fresh or proprietary facts → RAG / grounding;
  - consistent style or format, or a domain specialisation, with examples → fine-tuning;
  - high stakes → HITL.

## Exam wording & corrections
- The course table says fine-tuning 'improves a model's ability to be grounded'. More precisely: grounding ties each answer to verifiable sources at answer time (e.g. RAG, Google Search); fine-tuning changes the model's parameters/behaviour and does not by itself cite sources or add fresh facts.
- Exam rule of thumb: fresh or proprietary facts → RAG/grounding; consistent style, format or task behaviour → fine-tuning.
- The exam guide also names **prompt tuning**: a lightweight tuning method that learns a small set of extra 'soft prompt' parameters while the base model stays frozen. Not the same as prompt engineering.
