# 5.2 A brief history of agents
Course 5 · activity 646163 · video summarised

## Two kinds of agents
| | **Deterministic** (traditional) | **Generative** |
|---|---|---|
| Basis | **Predefined paths and actions**; workflow-based, **event-driven** | Gen AI model (LLM) understanding of meaning and **intent** |
| Behaviour | **Same input → same output**. High **control and predictability** | Some randomness and creativity; may answer the same input differently |
| Build effort | Tedious: teams hand-design every step, decision trees, logic | Far less scripting |
| Weakness | Fails on **atypical questions** ("speak to a live agent!") | Needs grounding for relevance and freshness |
| Example | IVR phone menus ("press 1 for scheduling…") | Modern conversational agents |

## Evolution (exam: order these)
1. **Deterministic agents:**
   - **Reasoning loop + tools only, no gen AI model.**
   - They often still used *non-generative* AI: speech-to-text, **keyword-based intent matching**, text-to-speech.
2. **Generative agents without RAG:**
   - Add the **model**, which brings natural-language understanding, so roundabout questions still work.
   - But the architecture meant models **couldn't integrate tool data into their knowledge**. Outputs were less tailored and **not up to date**.
3. **Generative agents with RAG:**
   - **RAG** connects model and tools: it accesses **external data sources**, giving **dynamic, up-to-date, grounded** answers.
4. **Today: hybrid agents.** The most complex agents **combine deterministic and generative capabilities**: deterministic reasoning logic and tooling plus generative abilities.

## Modern definition
A gen AI agent **achieves a goal by observing the world and acting on it with its tools**. It understands intent, accesses relevant information, and interacts naturally.

## The three components of an agent (exam core)
| Component | Description |
|---|---|
| **Foundational model** | The underlying LLM (small or large; Gemini or another provider's). Choose one whose **training data is relevant to the use case** |
| **Tools** | Let the agent interact with the outside world: **extensions** (APIs), **functions** (mock API calls), **data stores** (e.g. **vector databases**). They let it **observe and act** |
| **Reasoning loop** | The core decision-maker: iterates over goal, tools and gathered information. Frameworks like **ReAct (Reason and Act)** guide it |

## Knowledge check
Order oldest → newest: **Deterministic → Generative without RAG → Generative with RAG**.
