# 5.8 Adding in tooling
Course 5 · activity 646169 · video summarised

## Video
- A model plus reasoning logic **can't act in the real world by itself**.
- **Tools are the bridge** between the agent and the real world. They broaden tasks and improve accuracy and reliability.
- Examples: adjust smart-home settings, update calendars, fetch user information from a database, send emails.

## Four types of agent tools (exam core)
| Type | Definition | Example from the course |
|---|---|---|
| **Extensions (APIs)** | Bridge agent ↔ **external APIs** (rule sets for how software interacts) in a **standardised way**, whatever the API's design | A travel agent uses an extension for a travel company's API to find and book flights |
| **Functions** | **Specific actions** the agent can perform. The reasoning system picks the right one. Encapsulate logic; reusable | `calculate_price(flight details, passenger info)` → total cost |
| **Data stores** | **Access to information**: real-time, historical, knowledge bases. Keep answers accurate, relevant, current | Weather, stock prices, a customer database |
| **Plugins** | **Add new skills or integrations**: specific services, specialised tools, platforms | A calendar plugin to schedule; a **payment-gateway** plugin to process transactions |

**Matching quiz:**
- connect to external services via APIs → **Extensions**;
- define specific actions → **Functions**;
- access information → **Data stores**;
- add new skills and integrations → **Plugins**.

## How the reasoning loop uses tools (ReAct cycle)
1. **Reasoning (tool selection):** analyse the task and pick from the available extensions, functions and data stores.
2. **Acting (tool execution):** call the API, function or query with the needed inputs.
3. **Observation:** the tool output becomes the observation.
4. **Iteration:** reason about next steps, perhaps different tools or more information. Repeat until done.

## Worked example: scheduling a garden consultation
- **Reasoning:** pick the **scheduling plugin** linked to the gardener's calendar.
- **Acting:** check next week's availability (30 minutes, weekdays). Pull the client's name and contact from the **customer database (data store)**.
- **Observation:** a list of open slots.
- **Iteration:**
  - Offer the slots. If the client's choice is taken, use a **function** to suggest alternatives or a waitlist.
  - On confirmation, book through the plugin and **email both parties**.

## Key takeaway
Tooling lets agents **act**: databases, purchases, social media, smart home, scheduling, travel booking.
